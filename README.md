# Python SAST Analyzer

Исследовательский прототип для анализа Python-кода без выполнения исследуемой программы. Требуются Python 3.10+ и PyYAML.

## Запуск в VS Code

Откройте папку `prototype` в VS Code, откройте `analyzer.py` и нажмите ▶ **Run Python File** в правом верхнем углу редактора. Запуск без аргументов открывает меню в терминале: введите путь к файлу или папке, либо нажмите Enter для проверки `examples`. После проверки можно сохранить JSON-отчёт: `y` — да, `n` или Enter — нет. Для выхода введите `0`. Выберите интерпретатор Python с установленным PyYAML.

Путь в меню отсчитывается от папки `prototype`, поэтому запуск работает и при другой текущей папке терминала.

## Запуск командами

```bash
python3 -m pip install PyYAML
python3 analyzer.py examples --output example_report.json
PYTHONPATH=.. python3 -m unittest discover -s tests -v
python3 benchmarks/benchmark.py
python3 benchmarks/benchmark.py --fixtures benchmarks/dataset
```

Команды запускаются из каталога проекта `prototype/`. Можно передать один файл или каталог. При обходе каталога пропускаются `.git`, виртуальные окружения, кэши и каталоги сборки. Синтаксическая ошибка в одном файле попадает в `errors` и не останавливает сканирование.

## Структура

- `analyzer.py` — совместимый публичный API, обход файлов, CLI и JSON-отчёт;
- `scanner/rules.py` — однократная безопасная загрузка, валидация и индексация YAML;
- `scanner/imports.py` — разрешение импортов и лексических имён;
- `scanner/flow.py` — абстрактные значения, потоки данных, ветвления и простые вызовы функций;
- `scanner/engine.py` — проверка контекстных условий правил и формирование результатов;
- `rules.yaml` — 22 правила, источники и контекстные операции обработки;
- `tests/` — регрессионные тесты и размеченные безопасные/уязвимые файлы;
- `benchmarks/benchmark.py` — расчёт TP, FP, TN, FN, precision, recall, F1 и времени; `benchmarks/dataset/` — расширенный набор из 30 случаев по всем 22 правилам.

Исходные идентификаторы `PY-CMD-001`, `PY-SECRET-001`, `PY-DESER-001`, формат `match` и поля прежнего JSON-отчёта сохранены. В предупреждения добавлены `category`, `message`, `code`, а для потоков данных — `taint` с источником, строкой, цепочкой и sink. Порядок предупреждений стабилен.

## Правила и алгоритм

`rules.yaml` содержит списки `rules` и `sources`, отображения `sanitizers` и `contexts`. Для каждого правила обязательны `id`, `name`, `cwe`, `severity`, `description`, `recommendation`, `match`; `category` необязательна. `match.kind` задаёт тип проверки (`call`, `assignment`, `taint`, `config`), `function` или `target` задаёт sink/имя, а `predicate` — условие. Допустимые предикаты перечислены в `scanner/rules.py`; каждому соответствует отдельный обработчик в `scanner/engine.py`. Для правила с `keyword_true` можно указать `skip_if_tainted_argument: true`, чтобы не дублировать предупреждение более точного правила о недоверенном аргументе. Python-код из YAML не исполняется. Источники: `input`, `request.args/form/json/values`, `os.environ`. `shlex.quote` учитывается только для контекста командной строки. Проверка конечного списка допустимых значений сужает значение только в истинной ветви `if`.

Анализатор строит AST один раз на файл. Для выражений он вычисляет абстрактное значение с множеством источников и отметками обработки. Значение передаётся через присваивания, включая `:=`, конкатенацию, f-строки, `format`, коллекции, генераторы списков и множеств, именованные и собранные аргументы (`*args`, `**kwargs`), а также возврат простых функций. Обрабатываются захваты переменных в `match/case`. После альтернативных ветвей состояния объединяются по принципу «возможно недоверенное». Для циклов выполняется один абстрактный проход с объединением входного и выходного состояний. Тела классов и методы также проверяются. Псевдонимы `import` и `from ... import` разрешаются в области видимости, а локальные объявления закрывают импортированные имена; повторное присваивание или импорт обновляет привязку имени.

Проверки включают Command Injection, SQL Injection, Path Traversal, секреты в коде, десериализацию, Code Injection, слабое хеширование паролей, генерацию секретов через `random`, TLS, debug и небезопасные временные файлы. Предупреждение означает основание для проверки, а не доказанную эксплуатацию. Например, унаследованное правило `PY-DESER-001` по совместимости отмечает любой `pickle.loads`, даже если вход доверенный.

## Ограничения

Анализ ограничен одним файлом и глубиной трёх вложенных вызовов пользовательских функций. Нет межфайловых сводок, полноценного CFG, точной модели исключений и итераций до неподвижной точки, точного разрешения динамических атрибутов или проверки достижимости. Захваты `match/case`, генераторы и `*args`/`**kwargs` обрабатываются приближённо: анализатор может считать значение недоверенным в более широком наборе путей, чем при выполнении программы. Глобальные/`nonlocal` присваивания и алиасы объектов обрабатываются неполно. Нормализация и проверка допустимого каталога для пути пока не распознаётся как надёжная защита. Поэтому возможны FP и FN; особенно для динамического Python и сложных функций. В бенчмарке TP, FP и FN считаются по находкам `(файл, строка, правило)`, а TN — по безопасным файлам; их сумма не обязана равняться числу файлов. Небольшой набор `tests/fixtures` служит smoke-тестом, поэтому его метрики не следует переносить на реальные проекты.
